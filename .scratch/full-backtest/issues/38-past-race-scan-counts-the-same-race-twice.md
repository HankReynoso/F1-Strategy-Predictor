# 38: Past-race history counts the same race twice under circuit aliases

**What to build:** The router scans past seasons once per alias name (ticket 16), and the OpenF1 meeting lookup matches by substring across `meeting_name`, `location` and `country_name`. For Singapore, both "Singapore" and "Marina Bay" find the same 2023 meeting, so its Pit Loss and Historical Degradation samples are counted twice for 2024 and 2025 races. Monaco/Monte Carlo and Miami/Miami Gardens are likely affected too. Each past race must contribute once, however many aliases match it.

**Criterion 1: the double count, proven from the warm caches.** A scratch script resolved every alias name of every group in `location_aliases.LOCATION_ALIAS_GROUPS`, for each past season a 2023–2025 race reads (2022 through FastF1's exact `Location`/`EventName` match, 2023–2024 through `_find_meeting`). The only double counts were Singapore 2023 and 2024. "Singapore" is OpenF1's `country_name` and sits inside `meeting_name` ("Singapore Grand Prix"), while the location is "Marina Bay". The ticket's two guesses did not hold:

- Monaco/Monte Carlo: "Monte Carlo" is OpenF1's `circuit_short_name`, which the lookup never read.
- Miami/Miami Gardens: 2023 and 2024 are "Miami", and "Miami Gardens" is the longer string, so it can't be a substring of them. The reverse ("Miami" inside 2025's "Miami Gardens") did match. But no 2022–2025 race reads 2025 as history, so it never caused a double count.

2022 races are not affected either way. They go through `fastf1_loader._past_races_at_circuit`, which filters the schedule with `Location.isin(group)`, so each row appears once.

A wider check over every 2023–2025 OpenF1 location plus its aliases found no substring match that reached a different venue. The only loose matches were "Singapore" (2023, 2024, 2025) and "Miami" (2025).

**Decisions and alternatives rejected.**

- *Exact match on `location` or `meeting_name`, not on `country_name`.* Every caller in `src/`, the tests and the notebook passes a location ("Monza", "Baku") or a meeting name ("Singapore Grand Prix"), which is what `list_season` returns. A country is not an event: in 2023 "United States" covers Miami, Austin and Las Vegas, and "Italy" covers Imola and Monza.
  - Rejected: keeping the substring test and adding a rule such as "prefer an exact match, then fall back to substring". That keeps the failure mode for names that don't match exactly.
  - Rejected: matching on `circuit_short_name` too. It would make "Monte Carlo" reach Monaco and add a second route to the same race, which is the bug this ticket fixes. The alias group already covers that rename.
- *De-duplicate by the source's race identity even though exact matching alone removes today's double count.* The criterion asks for it, and it makes the guarantee independent of how either source matches names. If a future alias group or schedule string ever reaches the same race twice, it still counts once. The identity is the OpenF1 race `session_key` (the session the samples are read from) and the FastF1 `(season, RoundNumber)`. Both are stable keys the source assigns itself.
- *`race_id` is a string with a default of `None`.* A string reads well in a failing assertion or a log. The default keeps the roughly 15 hand-built `PastRaceSamples(...)` in older tests valid. A sample with `race_id=None` (only hand-built test fakes) is never de-duplicated. Making it required belongs in ticket 45, which already moves `PastRaceSamples` and replaces the bare tuples.
- *De-duplicate per season, not across seasons.* A race belongs to one season, and keying per season keeps "two different races at one venue in one season" possible. `test_two_different_races_in_one_season_both_count` pins that.
- *De-duplication in all three loops* (router same-era, router pre-era, OpenF1-only scan), each with the same three lines. Ticket 45 merges them. Doing it here keeps this change to matching and de-duplication, as asked.
- *Before/after via `git archive HEAD` and `PYTHONPATH`, not `git stash`.* Same reason as ticket 37: the working tree stays untouched while the before run happens.
