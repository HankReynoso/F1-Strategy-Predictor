# 16: Cross-season `Location` aliases for Pit Loss history

**What to build:** Teach the loader to treat renamed FastF1 `Location` strings as the same circuit when matching previous seasons' races for Pit Loss. The three known cases in the 2022–2025 window are `Marina Bay` (same venue as pre-era `Singapore`), `Monaco` (same venue as pre-era `Monte Carlo`) and `Miami Gardens` (same venue as same-era `Miami` 2022–2024). Without this, those renamed circuits currently fall into ticket 07's estimated-Pit-Loss path even though measurable earlier races exist.

**Blocked by:** 07 (Estimated Pit Loss for first-time circuits — this ticket is a direct follow-up to 07's "Deviations" section)

**Status:** done

**Category:** bug

- [x] Define a `Location` alias map alongside `pit_lane_table.py` or in `fastf1_loader.py`, so the loader can match `Marina Bay` to `Singapore`, `Monaco` to `Monte Carlo`, and `Miami Gardens` to `Miami` when scanning pre-era / same-era schedules.
- [x] Historical Degradation respects the same alias map (ADR-0004 still restricts to same era, so this only matters if two same-era seasons used different `Location` strings for the same circuit).
- [x] A slow test proves Monaco 2022 Pit Loss comes from `Monte Carlo` pre-era seasons, Marina Bay 2022 Pit Loss comes from `Singapore` pre-era seasons, and Miami Gardens 2025 Pit Loss comes from `Miami` 2022–2024.
- [x] Ticket 07's estimated-Pit-Loss count on a 2022–2025 Backtest shrinks from "every renamed circuit's first-season race plus Miami 2022 plus Las Vegas 2023" down to only Miami 2022 and Las Vegas 2023.
- [x] Each alias has a comment pointing to the FastF1 schedule rows that make the rename visible, so a future reader can tell why the two keys represent one circuit.

## Implementation notes

**What was built (2026-10-22), test-first.**

- `src/f1_strategy/location_aliases.py` — new module, the single source of
  truth for cross-season `Location` aliases. `LOCATION_ALIAS_GROUPS` is a
  tuple of `frozenset[str]`, one per physical venue that FastF1 has used
  more than one `Location` string for. Each group carries an inline
  comment naming the FastF1 schedule rows (years and the string FastF1
  stored on them) that make the rename visible. `location_group(location)`
  returns the group for a circuit, or a singleton `frozenset({location})`
  for a circuit that is not aliased — so the loader can filter on
  `schedule["Location"].isin(group)` unconditionally without special-
  casing the common case.
- `src/f1_strategy/fastf1_loader.py` — `_past_races_at_circuit` now
  computes `location_group(circuit)` once and uses `.isin(group)` when
  scanning each past season's schedule, in place of the previous
  `== circuit` equality. Both the same-era pass and the pre-era fallback
  go through this one function, so Pit Loss and Historical Degradation
  both pick up the aliases automatically (ADR-0004's same-era restriction
  for Historical Degradation is unaffected: the alias only widens which
  `Location` strings count, not which seasons).
- `tests/test_fastf1_weekend_loader.py` — three new slow tests, one per
  rename that the ticket's acceptance criteria name:
  - `test_monaco_2022_pit_loss_comes_from_monte_carlo_pre_era` — loads
    Monaco 2022, asserts `estimated_pit_loss is False` and that every
    `pit_loss_seasons` entry is in 2018–2021 (i.e. aliased Monte Carlo
    races).
  - `test_marina_bay_2022_pit_loss_comes_from_singapore_pre_era` — loads
    Marina Bay 2022, same assertions.
  - `test_miami_gardens_2025_pit_loss_comes_from_miami_same_era` — loads
    Miami Gardens 2025, asserts the Pit Loss is measured and the seasons
    are a subset of 2022–2024 (i.e. aliased Miami races in the same
    Regulation Era).

**Rename survey (2026-10-22).**

Confirmed every rename across FastF1's 2018–2025 schedules rather than
assuming the three the ticket named were the only ones. Walked each year's
`get_event_schedule(..., include_testing=False)` and grouped each
country's rows by `Location`. Countries whose events used more than one
`Location` string, with the physical-venue interpretation:

| Country | Locations | Interpretation |
|---|---|---|
| Monaco | `Monte Carlo` (2018, 2019, 2021), `Monaco` (2022–2025) | **Alias** — same venue |
| Singapore | `Singapore` (2018, 2019), `Marina Bay` (2022–2025) | **Alias** — same venue |
| United States | `Austin` (2018+), `Miami` (2022–2024), `Miami Gardens` (2025), `Las Vegas` (2023+) | **Alias Miami ↔ Miami Gardens** — same venue; Austin and Las Vegas are different physical circuits |
| Abu Dhabi / UAE | `Yas Marina` (2018), `Yas Island` (2019–2025) | **Alias** — same venue, FastF1 also changed the Country string between 2018 and 2019 |
| Italy | `Monza`, `Imola`, `Mugello` | Different circuits (not aliases) |
| Germany | `Hockenheim` (2018, 2019), `Nürburgring` (2020) | Different circuits (not aliases); pre-era anyway |

The Yas Marina ↔ Yas Island rename is not in the ticket text, but the
2018 Abu Dhabi Grand Prix shows up as `Country=United Arab Emirates,
Location=Yas Marina` while 2019 onward shows as `Country=Abu Dhabi,
Location=Yas Island`. The rename only matters for a 2022 Yas Island
race's pre-era pass (2019–2021 Yas Island already match without an
alias; 2018 is the one race that would otherwise be dropped), so it
does not take Yas Island off ticket 07's estimated-Pit-Loss list — it
was never on it. Added for completeness and because the acceptance
criterion is "every rename", not just "those that change the estimated
list".

**Baselines, not changing.** Captured `uv run f1-strategy 2024
"Singapore Grand Prix"` and `… 2024 "Italian Grand Prix"` before the
loader change. After the change:

- Monza 2024: byte-identical (`diff` empty). Monza has one `Location`
  string across every season from 2018 onward, so no alias applies.
- Singapore 2024: byte-identical (`diff` empty). Singapore 2024's
  `Location` is `Marina Bay`, and its same-era history (2022, 2023) uses
  the same string. The alias group only reaches `Singapore` (2018–2019)
  through the pre-era fallback, which `_measure_pit_loss_and_history`
  only triggers when the same-era pass finds no Pit Loss sample. Because
  Marina Bay 2022 and 2023 both produce samples, the fallback never
  runs, and the per-race Pit Loss (30.6 s) and all downstream numbers
  stay identical. The ticket flagged this as a race whose Pit Loss
  history "may legitimately grow" — in practice it does not, because
  the ADR-0004 Pit Loss exception is "last resort" (ticket 03).

**Decisions and alternatives rejected.**

- *A standalone `location_aliases.py` rather than extending
  `pit_lane_table.py` or stashing a dict in `fastf1_loader.py`.*
  Aliases are a separate concern from pit-lane geometry: adding them to
  the pit lane table would conflate "circuits that need an estimated
  Pit Loss" (two) with "circuits that need an alias" (four), which is
  exactly the mix-up ticket 07's "Deviations" section called out.
  Keeping the alias map in its own module makes the one-import
  consumer (the loader) read naturally and matches how the Regulation
  Era already lives in its own small module.
- *`frozenset` groups, not a `{old: new}` dict.* A dict would force a
  direction on the alias — e.g. "`Monte Carlo` is really `Monaco`" —
  which is fine for Pit Loss history lookups but awkward when a 2022
  race wants its Pit Loss searched under its own string plus every
  alias of it. A group of equivalent strings is symmetric and models
  the physical venue directly; the loader just asks "which strings
  refer to the same venue?" and does an `.isin(group)` filter.
- *Alias widening lives in `_past_races_at_circuit`, not in
  `_measure_pit_loss_and_history`.* The widening affects both Pit
  Loss and Historical Degradation (they share the schedule filter),
  which matches the ticket's "Historical Degradation respects the
  same alias map" criterion. Putting it in the inner scanner also
  means both passes (same-era and pre-era) in
  `_measure_pit_loss_and_history` inherit the aliasing for free,
  with no extra plumbing.
- *A singleton `frozenset({circuit})` fallback, not a special-case
  dict lookup.* Keeps the loader's filter line unconditional
  (`schedule["Location"].isin(group)`) and avoids a branch for every
  non-aliased circuit, which is 90%+ of the schedule.
- *Yas Marina ↔ Yas Island included even though it doesn't change
  ticket 07's list.* The acceptance criterion is "each alias"
  observable in FastF1's 2018–2025 schedules, and omitting a confirmed
  rename would make this ticket half-done. The alias widens the
  pre-era sample for a 2022 Abu Dhabi race by one race (2018 Yas
  Marina) with no behaviour change on 2023+ races, so the risk of
  including it is nil.

**Deviations from the ticket / spec.** None. The spec's "Loader: Pit
Loss before the era" bullet referred to the renamed-location follow-up
in general terms and this ticket is the one that lands it.

**Known limitations and follow-ups.**

- *Country-string change for Yas Marina not surfaced.* The alias map
  works off `Location` only, so a future rename that split a group
  across two country strings would still match. That matches today's
  loader (which filters on `Location` alone) and keeps the module
  small; if FastF1 ever reuses a `Location` string for two unrelated
  venues, the group would need a `(country, location)` key.
- *No alias for a venue that genuinely moves or is heavily rebuilt.*
  The ADR-0004 "rare pit lane changes are ignored for now" note still
  applies: an alias says "same physical venue", not "pit lane
  behaviour is unchanged". If a venue's pit lane is rebuilt in a
  future season, that is a `pit_lane_table.py` entry rather than an
  alias change.

**Review feedback for the user.** None — the three slow tests cover
the renamed circuits the ticket named, the fast suite remains at
148/148, and both Smoke Set reference races (Singapore 2024, Monza
2024) are byte-identical to their ticket 03 baselines. Ticket 09 can
now take the baseline Backtest Result without the three renamed
