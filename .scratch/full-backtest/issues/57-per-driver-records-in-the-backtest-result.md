# 57: The Backtest Result has no per-driver records to explain misses

**What to build:** Decide whether a Backtest Result should keep a short record per scored driver, so the reasons for misses can be read from the saved file instead of rebuilt. Ticket 24's analysis needed the prediction for every driver of every race. It got them by re-running `load_weekend`, `predict()` and `compare()` over all 80 scored races from the warm cache in a scratch script. The run takes under 2 minutes; the cost is writing and checking the script each time. Every finding behind tickets 50–54 came from those per-driver fields:

- the Remaining Sets rule used (new-only, used-set fallback, unfiltered fallback)
- whether the actual Strategy was a Candidate, and its rank
- the size of the top tied group
- the matched Stop Windows against the actual stop laps
- each Compound's Degradation rate and source

**Blocked by:** None (needs a decision first)

**Status:** needs-triage

**Category:** enhancement

- [ ] A decision is recorded in ADR-0005: save per-driver records in the data file, in a separate file, or not at all (re-run on demand). The trade-off is file size (about 1,600 driver records for four seasons) against the ADR's rule of scores only, never raw timing data
- [ ] If saved, the compare command can say which drivers' outcomes changed, and the readable summary stays as short as today
- [ ] If not saved, the re-run script becomes a supported command, so the next analysis doesn't rebuild it
