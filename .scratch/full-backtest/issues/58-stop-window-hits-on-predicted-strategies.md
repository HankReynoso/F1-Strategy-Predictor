# 58: Report Stop Window hits on predicted Strategies, and window width

**What to build:** Two extra figures in the Backtest Result, so Stop Window quality can be judged apart from Strategy Match. Today Stop Window hits are counted over all actual stops, but only stops on Strategies the model predicted can ever be hits (738 of 2,557 in the 2026-10-27 baseline). And a window spanning most of the race (e.g. "lap 5–57") counts as a hit almost by default. Keep the hit rule unchanged; add:
- Stop Window hits over stops on correctly predicted Strategies only (the actual Strategy is a Candidate Strategy)
- the average Stop Window width (laps) over those stops

Both appear in the headline, every breakdown, the saved Backtest Result and the compare command.

## Implementation notes

**What was built (2026-10-27), test-first.** 15 tests were written first and all failed because the feature was missing. They pass now.

- `src/f1_strategy/scorer.py`: `DriverScore` gains `stop_windows`. It holds the matching Candidate Strategy's planned stops, the windows each actual stop was scored against, and is empty when the actual Strategy isn't a Candidate. The hit rule and every existing field are unchanged.
- `src/f1_strategy/backtest.py`
  - `RaceResult` gains `predicted_strategy_stops` and `stop_window_laps`. The first counts the scoreable drivers' stops on a Candidate Strategy. The second sums the widths of those stops' Stop Windows, both ends counted. Both are `None` when not recorded.
  - `ScoreTotals` gains the same two fields. Hits over Predicted-Strategy Stops reuse the numerator `stop_window_hits`, because every hit is a Predicted-Strategy Stop. The average width is `stop_window_laps / predicted_strategy_stops`.
  - `RaceAveraged` gains `predicted_strategy_hit_rate_sum`, `stop_window_width_sum` and `races_with_predicted_strategy_stops`. These are the mean of each race's own rate and average width, over races with at least one Predicted-Strategy Stop.
  - Every total (green headline, race-averaged, Neutralised, all races, season, circuit, sprint/conventional, Tuning, Held-out) is built by the same `_totals` / `_race_averaged`, so all of them carry both figures.
  - `format_backtest` prints two more lines under every "Stop Window hits" line:
    - `Stop Window hits on predicted Strategies: 2/3 stops (67%)`
    - `Average Stop Window width: 9.7 laps (29 laps over 3 stops)`
    - The race-averaged forms are `mean 67% over 1 race(s)` and `mean 9.7 laps over 1 race(s)`.
    - When the figures weren't recorded, both lines read `not recorded (saved before format version 3)`.
- `src/f1_strategy/backtest_io.py`: `FORMAT_VERSION = 3`. Versions 1–3 are readable. Each race saves `predicted_strategy_stops` and `stop_window_laps`, which are required at version 3; a version-3 file without them raises `KeyError`. Older files load with both as `None`.

**Decisions and alternatives rejected.**
- *Bump to version 3.* ADR-0005's rule: a missing count would read as "0 Predicted-Strategy Stops", a real value. Rejected: optional keys at version 2, for the same reasons as ticket 39.
- *`None` for "not recorded", carried through every aggregate.* An old file can't be backfilled, because the figures need per-driver Candidate Strategies, which a Backtest Result never saves (ticket 57 would change that). Rejected alternatives:
  - Defaulting to 0, which would print a 0% hit rate over 0 stops for the baseline.
  - Hiding the lines for old files: the ticket asks the compare to say so, and an absent line is easy to miss.
- *No new numerator field.* Hits over Predicted-Strategy Stops have the same numerator as the existing figure, since a stop on a non-Candidate Strategy is always a miss. Only the denominator is new, so the two figures can't drift apart.
- *Windows exposed on `DriverScore`, not re-matched in the Backtest.* This keeps the one "first Candidate whose Strategy equals the actual one" rule in the scorer. Rejected: repeating the match in `backtest.py`, which would let the two drift. The field is additive and defaulted, so `compare()`'s existing outputs are unchanged.
- *Width counts both ends.* "lap 5–5" is 1 lap and "lap 5–57" is 53. Rejected: `last − first`, which makes a one-lap window 0 laps wide and reads oddly in an average.
- *"Correctly predicted" means the actual Strategy is any Candidate Strategy, as the ticket says, not only the top-1.* Those are the only stops whose windows are scored at all.
- *The race-averaged width is a mean of per-race averages*, matching how the other race-averaged figures are built (ticket 04). A race with no Predicted-Strategy Stops records 0, not `None`, and is left out of that average, the way a race with no stops is.
- *Seasons judged on.* No modelling option was chosen here, so no Tuning/Held-out comparison was made. The new figures report all seasons through the existing breakdowns.

**Deviations.** None from the acceptance criteria. Two additions the ticket didn't name: the scorer's new `DriverScore.stop_windows` field, and `WidthChange` (the change in laps isn't a percentage, so `ScoreChange.change_pp` didn't fit).

**Review feedback.**
- The two figures read best together. A high hit rate over Predicted-Strategy Stops with a wide average window is the "lap 5–57" failure ticket 54 describes. Read the hit rate next to the width, not on its own.
- When ticket 50 changes which Strategies are Candidates, Predicted-Strategy Stops will move too. A change in the hit rate over them is then partly a Strategy Match change, so compare the denominators as well as the percentages.
