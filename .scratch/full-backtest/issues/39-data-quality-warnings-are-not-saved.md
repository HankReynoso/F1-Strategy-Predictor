# 39: Data Quality Warnings are not saved in the Backtest Result

**What to build:** The per-race Data Quality Warnings (ticket 28 and 30) appear in the printed and `.md` summary but are never written to, or read from, the saved JSON. **Decisions and alternatives rejected.**

- *Bump to version 2 rather than add an optional field at version 1.* ADR-0005 as written let an additive, defaulted field stay at version 1. That doesn't work here, for two reasons:
  - An empty list would mean both "no warnings" and "this file never saved them". first-openf1-run is the second case: its `.md` lists eleven races' history warnings, and its `.json` holds none.
  - A build from before this change would read a new file and silently drop the warnings, which is this bug again.

  So the version is bumped and ADR-0005's Versioning section gets a rule: a field whose absence reads as a real value bumps the version.
- *Saved name `data_quality_warnings`, in-code name unchanged.* The triage note asks for the field to be "saved under its final name". Ticket 34 picks `data_quality_warnings` and `CONTEXT.md` names the term **Data Quality Warning**, so the file uses that name now. Renaming `RaceResult.history_warnings` itself is ticket 34's scope. It touches `backtest.py`, the report and tests outside this ticket, including OpenF1 test modules another session may be editing. It is now a code-only rename with no format change.
- *A missing key at version 2 is an error, not `()`.* Version 2 means "warnings recorded", so a version-2 file without them is malformed. It raises `KeyError`, like any other required field.
- *`format_version` on `RunMetadata`.* Without it the compare can't tell "no warnings" from "not saved". The next compare (ticket 24's rerun against first-openf1-run) would then flag every warned race as changed. Rejected alternatives:
  - A flag on `BacktestResult`: it describes the file, not the scores.
  - Having the compare reopen the files: the compare takes results, not paths, per ticket 06.
- *Compare names the races, not the warning text.* This matches the estimated-Pit-Loss warning. The text is in each side's summary, and a long diff would bury the other warnings. The warning only covers races scored on both sides, because "scored races differ" already covers the rest.
- *No recovery of version-1 warnings from the `.md`.* The data file is the source of truth (ADR-0005), and parsing the formatter's output would tie the loader to its layout.

**Deviations.** The ticket doesn't name `RunMetadata.format_version` or the "can't be compared" message. I added both so the compare criterion doesn't give a misleading result against the only committed file.
