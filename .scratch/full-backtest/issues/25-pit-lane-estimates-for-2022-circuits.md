## Implementation notes

**What was built (2026-10-23), test-first.**

- `src/f1_strategy/pit_lane_table.py` — the `PIT_LANES` tuple gains five entries: `Melbourne`, `Montréal`, `Spa-Francorchamps`, `Marina Bay`, `Suzuka`. Each cites its length source(s) and its speed-limit source in `source`; three (Spa, Marina Bay, Suzuka) carry a `note` saying what single-source caveat or inherited layout detail applies. The module docstring section explaining the table was rewritten to split entries into the ticket-07 "no earlier race at all" set and the ticket-25 "only pre-era history is 2018–2019 and no longer downloadable" set, with the baseline citation (commit e5e9699) attached so a future reader sees the provenance.
- `tests/test_estimated_pit_loss.py` — one new fast test `test_table_includes_the_2022_pre_era_only_circuits` asserts the five circuits are present. The existing `test_estimated_pit_loss_lies_in_the_calibration_band` widens the band from 18–28 s to 17–30 s so Melbourne's short pit lane and Spa's long pit lane both pass the sanity check, with the ticket-25 widening noted in the comment.
- `tests/test_fastf1_weekend_loader.py` — one new parametrized slow test, `test_2022_pre_era_only_circuits_use_the_pit_lane_table_estimate[event-location]`, runs through `load_weekend(2022, …)` for each of the five events and asserts `pre_race.circuit == location`, `pre_race.estimated_pit_loss is True`, `pre_race.pit_loss_seasons == ()`, and `pre_race.pit_loss == pytest.approx(estimated_pit_loss(pit_lane_entry(location)))`.
- `tests/test_fastf1_weekend_loader.py` — the ticket-16 named test `test_marina_bay_2022_pit_loss_comes_from_singapore_pre_era` was renamed to `test_marina_bay_2022_falls_through_to_the_pit_lane_table_estimate` and updated to reflect the new real-world behaviour: Marina Bay 2022's pre-era pass finds nothing (FastF1 can no longer download 2018/2019 Singapore live-timing data) and the loader uses the ticket-25 Marina Bay table entry. A paragraph in the test comment records that the ticket 16 alias group is still correct — it would pick those races up again if the pre-era pass becomes loadable later — so the alias module is unchanged.

**Decisions and alternatives rejected.**

- *Use the 2022 pit-lane configuration for Melbourne.* Albert Park was redesigned for the 2022 season with a widened pit lane, so the speed limit rose from 60 km/h to 80 km/h and the lane geometry changed. The table entry is only consulted when no previous race can be measured — in practice, the 2022 Australian GP — so the 2022 geometry (281 m, 80 km/h) is what applies. The pre-2022 figures (McLaren's 280 m is pre-widening-width; the 2014 Mercedes 289 m is pre-widening-length) sit within rounding of the modern figure for the formula's purposes but were not chosen as the source. The entry's `source` field names TracingInsights' 2024 figure as primary, since it is post-redesign.
- *Use the 2022 Marina Bay speed limit (60 km/h), not the 2025 raised 80 km/h.* The table entry is only consulted for Marina Bay 2022 (every later season has 2022 Marina Bay in same-era history, so the measured path handles them). The 60 km/h figure is the one the FIA set for the 2022 Event, so the estimate matches the race it is used for. The 2025 raise is called out in the entry's `source` text so a reader does not mistake the 60 for an error.
- *Use the speed-limited section length for Montréal (400 m), not Oversteer48's 741 m "pit-entry to pit-exit" figure.* Ticket 07's formula already accounts for the slow-in and slow-out zones outside the speed-limited section in its fixed `SLOW_IN_OUT_PENALTY_S` term, so feeding it a length that includes those zones would double-count them. The `note` on the Montréal entry says so explicitly, so a future reader does not swap one figure for the other and see Pit Loss jump by ~7 s.
- *Spa's length left at Oversteer48's 653 m.* No second F1-specific source gave a comparable figure (the GT4 European Series' 994 m applies to the endurance pit-lane layout, which shares the F1 pit lane with the old pit on the inside of La Source, and is not what the formula wants). The entry carries that caveat in its `note`. The resulting estimate of 29.0 s is high but matches Spa's reputation as the longest pit lane on the F1 calendar; the published F1-Fansite figure of 19 s is for a different quantity (pit-lane transit time only, not total Pit Loss) so the two are not directly comparable.
- *Widen the fast-test calibration band from 18–28 s to 17–30 s, rather than exempt specific circuits.* The band is a sanity check on the formula's output, not a tuning target; Melbourne 17.6 s and Spa 29.0 s are both legitimate values for the pit lanes they describe. Exempting named circuits would be the same thing with more rope to get wrong later; widening the band preserves the invariant "every entry's estimate is in a plausible range for an F1 pit stop".
- *No new domain terms added to `CONTEXT.md`.* The ticket re-uses `Pit Loss`, `Excluded Race` and the existing "estimated from pit lane length and speed limit" phrasing from ticket 07. No new concept crosses a seam.
- *No ADR change.* ADR-0004's Pit Loss exception already lets the formula read from the pit lane table; ADR-0006 (ticket 19, in flight in a parallel session) records the per-season data-source policy and the 2018–2020 download hole that motivates this ticket. This ticket is a direct consequence of that ADR, not a new decision of its own.

**Deviations from the ticket / spec.**

- *Spa and Suzuka's length figures are single-source.* The ticket says "a figure that can't be found from a reliable source is recorded as missing rather than guessed" — these figures do each come from a reliable source (Oversteer48 for Spa, McLaren's own 2016 preview on Racecar.com for Suzuka), but each is not corroborated by a second F1-specific source. The `note` on each entry calls this out so a future reader can replace the figure if a definitive FIA circuit document comes to light.
- *The spec's "Loader: estimated Pit Loss" bullet says "A circuit missing from the table, with no history either, is an Excluded Race with that reason."* Still true. This ticket just adds table entries for five circuits that were falling into "no history either" because FastF1's 2018–2019 data stopped being downloadable; the spec's rule, and ticket 02's `DATA_UNAVAILABLE` path, are unchanged. No spec update needed.

**Known limitations and follow-ups.**

- *The ticket-16 slow test for Monaco 2022 (`test_monaco_2022_pit_loss_comes_from_monte_carlo_pre_era`) still asserts the pre-era pass measures Pit Loss from 2018/2019/2021 Monte Carlo races.* In the current FastF1 environment that test still passes (Monte Carlo data is loadable), so Monaco is not in this ticket's five-circuit list. If FastF1's live-timing API ever drops Monte Carlo too, Monaco 2022 will become a sixth entry needing a pit-lane table row (Monaco: 190 m, 60 km/h is the well-known figure, but confirm against the FIA stewards' Monaco 2022 pit-lane-speeding decision before adding).
- *Spa and Suzuka single-source caveat.* If the FIA's event-day Technical Delegate's Report or a per-event homologation document surfaces for either venue, replace the length and drop the `note` — the formula re-runs against the new number without further changes.
- *The `test_measured_history_wins_over_a_pit_lane_table_entry` slow test was removed before merge.* My plan was to load 2024 Japanese GP and show Suzuka 2024 uses measured history (not the new Suzuka table entry). FastF1's current environment cannot load 2024 (or 2023) race data at all — the baseline file in commit e5e9699 shows every 2023+ race landing as `data unavailable — The data you are trying to access has not been loaded yet`, which is the same path a direct `load_weekend(2024, "Japanese Grand Prix")` hits now. So the "measured history wins" guarantee is still a code-level invariant of `_measure_pit_loss_and_history` (the table is only consulted after both prior passes return `None`), covered by the existing `test_a_2024_races_pit_loss_uses_only_same_era_seasons` for Monza when FastF1's post-2022 loading comes back (either through OpenF1 — tickets 20–24 — or an upstream FastF1 fix). This ticket is explicitly scoped to make the five 2022 races load, which the parametrized slow test proves.
